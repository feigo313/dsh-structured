# tone-v3 设置页评审（三路独立评审 + 交叉核验）

- 对象：`artifacts/prototype/tone-v3.html`（评审时 886 行）、`tone-v3-960.png` / `tone-v3-general.png`（旧版截图，部分已删除）
- 方法：三个子代理分别做「功能与架构」「视觉引导与设计感」「对抗性需求核验」，主会话对关键结论逐条回读源码验证

## 一句话结论

**6/10。方向对，但"调三句、看效果"这个核心闭环不成立**：1200 字的正文口吻改了预览一动不动；名称/头像改完不进保存；JSON 一错就把编辑器锁死。可演示，不够可评审。

## P0：五个硬伤

### 1. 正文口吻没有预览（最致命）

- `#positive`（1200 字核心字段）的 input 只更新 `state.doc` 和计数器（577），预览正文是写死的 `data-original`（378），`paint()` 只把它原样回填（572）。
- 后果：改口吻，预览零变化。"调三句、看效果"只剩两句有效。
- 修法：`renderProof(doc, mode, enabled)` 纯函数，正文行绑 `positive`（显示首句或截断摘要），不再用 `data-original`。

### 2. 名称与头像不进状态机，UI 却显示"已保存"

- `dirty()` 只比较 `enabled/template/doc`（482-484）；名称 handler 直写 `state.name` 和 `#chatName`（715-718）；头像只写 `state.avatar`（732）；`saved` 里有 name、没有 avatar（668）。
- 后果：改完名字/头像，保存条仍是"已保存 · 新消息生效"，保存按钮不出现；切模板时 `dirty()` 为 false，`applyTemplate` 不确认就覆盖（682-688）。
- 修法：`draft`/`committed` 同构（enabled/template/name/tag/avatar/doc），dirty 深比较；删 DOM 直写，统一由 render 投影。若产品拍板"改名不持久化"，UI 必须显式标注"仅本页预览"，不能两边各说各话。

### 3. JSON 无效态自锁编辑器

- 提示文案写"JSON 无效 · 修正后才能保存"（489），但 `setFieldDisabled(true)` 把 `#jsonText` 一起禁用（508/589），`#jsonToggle`、`#resetBtn`、`#enabled` 一并禁用。
- 后果：手打第一个 `{` 就冻结，唯一出口是丢弃修改。
- 修法：拆 `canEdit` / `canSave`；invalid 只禁保存和开关，textarea 始终可编辑。

### 4. Sessions 预览的形态当前插件做不出来

- `src/client.js` 只对已有 `_markdown_` 节点加 class/attr（4、8、111）；tone 是写进 system prompt 的普通文本（`src/index.js:143-145`）；宿主没有助手消息头的替换槽位。
- 预览却画了 30px 头像 + 显示名 + 角色标签 + 分层竖线（368-373）。
- 后果：评审看到的是做不到的样张。计划自己也写了要 spike（`PLAN:358`）。
- 修法：预览只画真实 markdown 输出；消息头要么先做宿主 spike，要么从预览里删掉。

### 5. 两个空动作

- "结构层常开 →"只弹 toast（863）。
- "复制"复制的是硬编码串（808），与卡内正文不一致，也不随三字段变化。
- 修法：删掉或接真实逻辑；复制从当前渲染结果取文本。

## 视觉引导

- 无 H1，最大字是 22px 的名字；"语气层"13px 在左上角当标题用，首屏先读到"角色档案"。
- 预览卡从 y≈847 起，正文 y≈925，结论卡标题 y≈983，被 y≈948 起的 52px 保存条压住。
- 左缘四条：24 / 85 / 120 / 480；档案卡 912、校样 790、编辑列 720，三套宽度。
- 8 档字号（22/18/16/14/13/12/11.5/10），12/11.5/10 挤在 2px 内；9 档圆角；5 处暖棕阴影。
- 模板入口是 13px 下划线单字"换"，首屏唯一的蓝色花在它身上；popover 盖住档案卡和第一个字段标签。

## 证据问题（必须修）

1. `tone-v3-general/dirty/off/invalid/readonly/800/1440` 六张图的 mtime 早于当前 HTML 约 46 分钟，仍带已被否决的封面 / @handle / 简介布局，不能作为本轮证据。
2. `tone-v3-960.png`、`tone-v3-avatar.png`、`tone-v3-saved.png` 三张 sha256 相同——"换头像""已保存"两个状态没有真正拍到。
3. `docs/1.0-TONE-V3-PLAN.md:355` 仍写"88px + 封面"，与 346-347 的"96px、不显示封面"冲突，实现者照 355 会做出封面。

## 只改三处（结构性）

1. **draft / committed 同构**：name/tag/avatar 进状态机，删 DOM 直写，dirty 深比较——一次解掉 P0-2、切模板静默覆盖、死字段。
2. **canEdit / canSave 分离 + 单一 `validateTone`**：解掉 P0-3 和两套校验。
3. **`renderProof` 纯函数**：从状态重算，ghost 用 data 原文，复制从渲染结果取文本——解掉 ghost 往返损坏、表格缺口吻、复制不一致。

不必动：三字段交互与文案、固定说明原文、模板三选一、30px 卡、三态规则——这几处是对的。

## 水平判定

- **可演示**：方向、层级、状态机讲得清。
- **不够可评审**：评审要求"看到的 = 真实行为"，而核心预览是静态样张，形态在目标架构内不可实现。
- **到可交付**：还差持久化、tone@1→@2 迁移、宿主接入、头像承载位。
