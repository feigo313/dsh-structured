# 1.0 基线（0.9.8 冻结版）

## 固定 10 条 prompt

1. P01：给一个 5 人团队做本周发布计划。
2. P02：解释一个 Redis 连接池泄露的排查顺序。
3. P03：比较 Postgres 与 SQLite 的适用边界。
4. P04：把一份长会议记录压缩成决策、风险和下一步。
5. P05：给一个前端页面做无障碍检查清单。
6. P06：写一个可回滚的数据库迁移方案。
7. P07：分析一段 Python 异步代码的死锁风险。
8. P08：给一个 API 设计写三组验收用例。
9. P09：用表格比较三种缓存策略。
10. P10：对一个失败发布做 5-Why 复盘。

## 注入口径（0.9.8）

当前 `BUILTIN_STYLE_TEXT` 940 字符；GenUI 路由 186 字符；尾部提醒 206 字符。合计 1332 字符，约 333 token（按 4 字符/token 估算；不是宿主 tokenizer 实测）。10 条 prompt 共用同一注入段，per-turn 注入增量以宿主实际 tokenizer 为准。

## 输出与结构化率

- 首屏结构化率、散文率：沿用 `docs/METRICS.md` 的 12 个新会话样本（注入 12/12，散文 0/12）；这是 0.9.x 既有样本，不是本轮 10 条固定 prompt 的新跑结果。
- 输出 token 增量：**未测**；本轮没有调用模型执行 10 条固定 prompt，不能用旧样本冒充。
- 3×2 桌面实机截图：**未验**；0.9.6 的视觉截图是 web profile 裁图，0.9.8 没有安装到 desktop。

## `style.md` 1.0 迁移语义（冻结）

- `style.md`：非空即整份覆盖内置 `BUILTIN_STYLE_TEXT`；不做片段合并。
- 需要保留结构规则时，把 `BUILTIN_STYLE_TEXT` 全文复制到 `style.md`，再追加自己的文本。
- 1.0 的 `persona.md` 只作为**追加层**设计，不改变 `style.md` 的整份覆盖语义；结构规则始终注入，见 `docs/1.0-PERSONA-SPEC.md`。
- 读取失败、文件为空、权限错误均 fail-open：回退内置规则，不阻断回复。
- 迁移路径：现有 `style.md` 用户不需要改文件；若 1.0 要同时使用结构规则和人格，按 1.0 spec 使用 `persona.md` 追加，而不是把人格塞进 `style.md`。
