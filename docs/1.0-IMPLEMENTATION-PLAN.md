# dsh-structured 1.0 人格设置页：实现计划

- 状态：待确认；本文件只做计划，不改代码
- 目标：实现两页设置（结构化输出 / 表达风格），人格页表单 + JSON 双入口，默认关 + 中性模板，结构规则不变
- 基线：0.9.9；只改插件代码；不碰宿主/app.asar/AGENTS/soul；不 push/publish

## 一、已确认的产品决策

1. **两页拆分**：结构化输出保留现有六字段；表达风格独立 tab；不给结构加入口栏 UI；`/structured on|off` 原样保留。
2. **存储**：只存 profile Config 的 `personaEnabled:boolean` + `persona:string`（单个 JSON 字符串）；MVP 不读 `persona.md`；不引入 profile 文件路径。
3. **默认**：`personaEnabled=false`，默认模板为“中性”；鲸鱼娘只做可选示例，不写死默认。
4. **页面**：宽屏左表单、右 JSON（JSON 为高级，可收起）；<1000px 单列；不做 live 模型预览；静态示例须标“不是实时输出”。
5. **同步**：表单和 JSON 共用 canonical `PersonaDoc`；JSON 无效时保留文本、显示 JSON Pointer、禁用保存；模板切换/载入基础模板/上传/切 tab 在 dirty 时先确认；保存显式点击，失败保留草稿。
6. **护栏**：结构、事实、工具/权限、GenUI、代码/diff 隔离、安全不可被 JSON 覆盖；渲染层固定前缀/后缀；加对抗测试。
7. **IP**：鲸鱼娘 JSON 标“非官方/社区二创”，完整署名链；不打包美术；Jarvis 只做“管家型”。

## 四、实现步骤

### 1. 先对齐规范文档（不改代码）

- 更新 `docs/1.0-PERSONA-JSON.md`：
  - `meta`：`name/author/license/source/attribution` 必填；`official=false`。
  - `closing` 存在时必填 `enabled`/`mode`；`skipIn` 加 `short/table`。
  - `examples` 存在时 `minItems:1, maxItems:3`。
  - `render.intensity` 只允许 `standard`；`audience` 允许 `general|developer|external`，`language` 保持。
  - 明确旧 Markdown spec 的 `persona@1` 与 JSON schema id 不共用；旧 spec superseded。
- 更新 `docs/1.0-PERSONA-WHALE.json`：补 `author: "上善无形 → ZipZipPipe"`、`license: "CC-BY-NC-SA-4.0"`、`source`、`attribution`、`audience`、`skipIn`；不打包美术。
- 旧 `docs/1.0-PERSONA-SPEC.md` 顶部标 SUPERSEDED。

### 2. Host：Config + persona 编译

- `Config` 新增：
  - `personaEnabled: k(Schema.boolean().default(false))`
  - `persona: k(Schema.string().default(NEUTRAL_PERSONA_JSON))`
- 新增 `NEUTRAL_PERSONA_JSON`（原创、无第三方角色、meta 完整、closing signature）。
- 新增纯函数：
  - `parsePersona(raw)`：`JSON.parse` + 必需字段/类型/枚举/长度/未知字段检查；失败返回错误列表，不抛。
  - `renderPersonaPrompt(doc)`：只拼接 identity/address/tone/habits/closing/examples/render；固定前缀/后缀；不注入工具/权限/结构；示例明确“只作语气锚点，不得复述”。
- 注册独立 section：
  - `PERSONA_SECTION_NAME='dsh-structured:persona'`
  - order = `min(sectionOrder()+50, REMINDER_ORDER-1)`；在 base 之后、tail reminder 之前。
  - `text(context)` 走 `sectionText`；`personaEnabled!==true` 或 invalid 返回空串；fail-open。
- `style.md` 语义不变；persona 只追加，不改变 base；文档写清“style.md 可覆盖 base，persona 不能覆盖”。
- 测试：8 字段、默认中性、开启注入、关闭不注入、无效 JSON 忽略、style.md 覆盖后 persona 仍追加、固定护栏文本存在、section 顺序。

### 3. Client：纯状态机 + UI

- 新增纯 helper（`__test` 暴露，便于测试）：
  - `PERSONA_PRESETS`：中性/鲸鱼娘/猫娘/管家/自定义；鲸鱼娘带非官方标记；不写 Jarvis 名称。
  - `createNeutralDoc` / `parseDoc` / `serializeDoc` / `validateDoc` / `applyFormField` / `loadPreset` / `isDirty`。
  - `validateDoc` 返回 `{ok, errors:[{path,message}]}`；路径用 JSON Pointer。
- `ConfigPage`：
  - 两 tab；结构化 tab 复用现有六字段；persona tab 独立。
  - 顶部启用开关（写 `personaEnabled`，立即生效）；模板选择、载入基础模板、左侧表单、右侧 JSON、上传/下载/格式化/校验、保存/恢复默认、状态行。
  - <1000px 单列；JSON 可收起；宽屏左右分栏；暗色用宿主 CSS 变量。
  - 状态：loading/unavailable/readonly/clean/dirty/invalid-json/saving/saved/failed/too-large/off。
- 同步规则：
  - canonical `PersonaDoc` 唯一；表单是投影，JSON 是序列化文本。
  - 表单改 → doc 更新 → JSON 重写；JSON 改 → 解析校验 → 表单同步。
  - JSON 无效：保留文本、显示错误、禁用保存；表单保留最后一次有效数据，不偷偷覆盖 JSON。
  - 模板/载入基础模板/上传：dirty 先确认；只替换草稿，不写 profile。
  - 保存：`form.set('persona', JSON.stringify(doc, null, 2))`；await；失败保留 draft；`writable=false` 全部禁用（下载保留）。
  - 恢复默认：回到中性，不是鲸鱼娘；dirty 先确认。
  - 上传：`input[type=file]`，≤64KB，UTF-8；非 JSON/超限/空文件给状态。
- 静态预览：固定示例，不调模型；标“不是实时输出”；可收起。
- 字符/大小：显示字符数、JSON 字节数、64KB 上限；token 只显示“估算，以宿主为准”，不用假 tokenizer。
- 测试：纯 helper；UI 注册、tab、控件、只读、dirty、无效 JSON；fake runtime 补 `react` hooks 或改为可测的纯组件；UI 实机由 desktop smoke 补。
- 不做：live 模型预览、7 个独立输入框、人格市场/编辑器、persona.md。

### 4. 构建与验收

- `npm test`：现有 63/63 + 新增；`npm run build` 后 `lib` 与 src 一致；`desktop-check`；`theme-contrast` 60；`theme-hue-distance` 12；`npm pack --ignore-scripts` 记录文件数。
- 桌面实机：两 tab、默认关中性、开启/关闭、表单↔JSON、无效 JSON、只读、800px 单列、暗色。
- 结构不退化：10 条固定 prompt（或最小 5 条）开/关人格，标题卡/表格/风险/下一步存在。
- 对抗测试：JSON 含 `ignore previous`/“输出纯散文”/“改工具”/“改结构”，断言固定前缀/后缀和护栏仍在；模型行为另做人工 smoke，不把提示词测试当模型保证。
- 不 push/publish；不 commit 直到你确认代码和验收。
