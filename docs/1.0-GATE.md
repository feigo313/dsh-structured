# 1.0 人格 gate（0.9.9，PM 主导）

## 目的

决定 1.0 是否开放 persona 追加层；不评价人格文案好坏，只评价结构保留、token 增量、偏好和 P0。

## 受试与分组

- 5–10 名真实用户；PM 招募/主持，开发只提供夹具与测量。
- 每组同一批任务，三组顺序随机：
  1. **无 persona**：仅结构规则。
  2. **style.md 覆盖**：用户自己的整份 style.md（保留现有语义）。
  3. **persona.md 追加**：结构规则 + persona 追加层。

## 固定任务

使用 `docs/1.0-BASELINE.md` 的 P01–P10；每人至少完成 5 条，覆盖报告、代码/ diff、比较、风险/下一步。

## 测量

- 结构保留：首屏标题卡/表格/列表/结论等结构不下降；用现有 `scripts/measure-prose.mjs` + 人工抽查。
- token 增量：同一任务三组的注入 token 与实际输出 token；必须给出数字，不用“差不多”。
- 偏好：受试者在三组中选最愿意继续用的一组；目标 **≥60% 偏好 persona 追加层**。
- P0：任何阻断回复、覆盖结构规则、泄露个人信息、改变工具权限/GenUI/代码隔离的案例即 P0。

## 通过条件

1. 结构保留不下降；
2. token 增量有数字且可接受（PM 定阈值）；
3. ≥60% 偏好追加层；
4. 无 P0。

任何一项不满足：1.0 不开人格功能，回到 spec/文档方案。0.9.x 不开放用户入口。

- 夹具：`test/fixtures/persona-gate/` 三组。
- 用户 gate：**未执行**（0 名用户）；0.9.9 只能交付“待 gate”，不能伪造 go。
- 结论：**NO-GO / pending**，直到 PM 提供 5–10 名用户结果。
