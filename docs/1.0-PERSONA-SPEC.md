# 1.0 人格化 spec / schema（0.9.9 草案，不实现）

## 定位

1.0 的人格是 **profile 级追加层**，不是替换层：

1. 结构规则：始终由 base 注入。base 默认是 `BUILTIN_STYLE_TEXT`；`style.md` 非空时按现有契约整份覆盖 base（显式例外，用户自己承担丢失结构规则）。
2. `persona.md`：只追加在 base 之后，不能删除、替换结构规则，不能修改 host 提示词或消息内容。
3. 不碰 `AGENTS.md`、`soul`、工具权限、GenUI 路由和代码/diff 隔离。

## 路径与读取顺序

- profile 级路径：`$DSH_PROFILE_DIR/dsh-structured/persona.md`；缺省 profile 目录时按宿主 profile 解析，不读其他 profile。
- 读取顺序：base（内置或 `style.md` 整份覆盖）→ `persona.md` 追加层。
- 两个文件都存在时，`style.md` 仍只控制 base；`persona.md` 不参与 base 覆盖。
- 读取失败、权限错误、文件缺失、schema 不合法：忽略 persona，继续 base，fail-open，不阻断回复。

## Schema

`persona.md` 是 UTF-8 Markdown，可选 frontmatter：

```yaml
---
schema: dsh-structured/persona@1
scope: profile
append: true
recommended_max_chars: 4000
---
# 称呼与语气
...
```

- `schema` 必须精确匹配 `dsh-structured/persona@1`；不匹配时忽略并记录一次非阻断警告。
- `append` 只能为 `true`；`false` 不提供“替换结构”的入口。
- `recommended_max_chars` 只是建议；**不硬截断**。超过建议值时在设置页显示提示，不改变实际内容。
- 正文只作为文本 section 追加；不插值 `{{...}}`，不执行命令，不解析 Markdown 到 DOM。

## 优先级与迁移

1. 结构规则：`BUILTIN_STYLE_TEXT`（默认）或 `style.md`（整份覆盖）。
2. `persona.md`：追加层，不能覆盖 1。
3. 其他 profile/全局文件：不参与。

迁移：

- 现有 `style.md` 用户不需要改文件；0.9.x 不读 `persona.md`，行为不变。
- 1.0 想保留结构规则并加人格：保留/复制 `BUILTIN_STYLE_TEXT` 到 `style.md`，把人格写进 `persona.md`；或保持 `style.md` 为空，使用内置结构 + persona 追加。
- 不建议把人格塞进 `style.md`，否则会整份覆盖结构规则。

## 隐私与安全

- persona 可能包含个人信息；只保存在本机 profile，不进入 npm 包、不写日志、不上传、不进市场。
- 文档和设置页必须提示“persona 可能含个人信息，分享 profile 前先清理”。
- persona 不能包含工具调用、系统指令覆盖、凭据或外部 URL 执行语义；仅作为文本追加。

## 0.9.9 不实现

- 不加设置页入口、不新增命令、不做人格市场/编辑器/预设包、不读 `persona.md` 运行时。
- 只提供本 spec、三组 gate 夹具和测量口径；1.0 是否上线由 gate 决定。
