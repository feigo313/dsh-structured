# 语气风格页 v3 · UX 评审（960 单列）

- 日期：2026-10-29
- 对象：`artifacts/prototype/tone-v3.html`（截图取自 10-28 22:54 版：960 / 800 / 1440 × 1000，含 saved / dirty / off / invalid / readonly / proof）
- 对照：`artifacts/prototype/zcode/tone-a.html`、`tone-b.html`
- 方法：一个 persona 从头到尾走一遍 + 能从代码量出来的部分（字号清单、对比度、内容高度、列宽）
- 边界：**没有在真实宿主里渲染**。宿主的插件头 / tab 一定比原型自绘的那 100px 更高，所以下面所有「首屏还剩多少」的结论都是上界，实机只会更紧。这是定性判断，不是 A/B 结论。

## 0. 一句话

这一页的问题不是「太挤」或「字太小」，是单列把「改一句、看一句」逼成了每次往返，而它没有让输入看起来像结果，所以用户必须先去下面确认，再爬上来到上面修改。

Boss 提的四条判断我都复核了，其中两条要对准病灶：

| Boss 的判断 | 复核 | 更准的说法 |
| --- | --- | --- |
| 校样在首屏外 | 成立，且是 0 行 | 960×1000 下校样正文起点在 y≈950，被 sticky 保存条压住；用户看到的是「校样 PROOF」四个字和三个 tab |
| 字号小 | 成立 | 20 种字号，81/95 条声明落在 7.5 至 12.5px 这 5px 带里；关键提示还只有 3.6:1 对比度 |
| 层级平 | 成立，但原因相反 | 不是档位太少，是档位太多而区间太窄：13.5 / 13 / 12.5 / 12 / 11.5 之间看不出差别 |
| 像密集表单 | 成立 | 3 个字段用了 12 个微标签（角色徽 / 名称 / 键名 / 提示 / 看校样）×4 种字号，全部塞在 172px 里 |

## 2. 五秒测试

1. **这是什么？** 能。语气风格 +「不改模型怎么想，只改它怎么说」，第二句话就把边界说清了，这是全页最好的一句。
2. **是给我的吗？** 大概是。但「蓝色大肥鱼」「本鲸鱼娘可不背锅」是别人的口吻，我还不知道能不能改。
3. **我该做什么？** **不能。** 四个动作并列：选模板 / 打开关 / 填三句 / 看校样，眼睛没有落点；而我最想做的「先看看长什么样」在屏幕外。

第三问不过，不是缺按钮，是四个「下一步」互相抵消，加上结果不可见。按 Fogg 记：M 高（他就是要这个）、A 中（写口吻难，但逐字填不难）、**P 不明**。要修的是 P，不是再加激励。

## 4. 960 单列：结构与节奏的取舍

### 4.1 单列真正买下的成本

双列时「改」和「看」是并置，一次改动 0 次滚动；单列时是顺序，一次改动 = 向下一次 + 向上一次。改三处就是六次。这是锁定决策必须付的钱，只有两种还法：

1. 把结果搬到输入旁边。违反「上功能下校样」，也打击回头用户（他一进来找的是输入框，不是图片）。
2. **让输入本身长得像结果。** 唯一不违反约束的还法。

所以单列下「三句话」不能是一个表单表格，它必须兼职预览。这不是审美选择，是结构必然。现在的 172px 标签栏正好把这件兼职取消了：它把每条输入框左边钉了一排标注，读起来像在填参数表，而不是在写一句话。

### 4.2 空间的算术

现状内容高约 1200px（tone-shell 顶到校样底），拆开是：

```text
标题块 115 · 起点 150 · 三句 390 · 说明 40 · 进阶 40 · 校样 460
```

其中 390 是「必须改的东西」，460 是「必须看的东西」，其余 320 是导航和说明。目标 ~800：

```text
状态行 44 · 三句 330 · 固定规则 22 · 校样 400
```

省下来的 400px 不是为了让页面变短，是为了让**首屏同时出现一处输入和一处输出**。按这个账，960×1000 下普通校样的标题卡 + 口吻 + 落款都能落在 1000 以内，不再需要「看校样」这个跳转。

### 4.3 节奏：三个密度，一个断点

现在全页只有一种密度：14px 内边距、1px 细线、8 至 12.5px 的字，从头到尾一模一样。于是每一段看起来同样重要，等于都不重要。

- **控制带**：12px 内距、13px 字、细线只用在输入框底边。
- **说明带**：6px 内距、11px 字，不要边框，靠留白分组。
- **结果带**：20px 内距、14 至 16px 衬线，换底色或加宽留白，让它一眼不是「表单」。

**断点只要一个**：三句和校样之间用 40px 空白切开，不要再用线。线已经用滥了，空白是这页唯一还能表示「这里换了一件事」的符号。

### 4.4 取舍清单

- **接受**：960 下校样不可能与输入全屏同见，除非把输入做成结果的样子。
- **放弃**：起点作为独立板块（降为标签 + 改）；基础视图里的键名（只留在 JSON）；说明整句（拆成规则行 + 校样图例）。
- **不放弃**：三态校样。它是这页唯一能证明「规则真的生效」的东西，比 zcode B 的「示例」徽标强。
- **要防**：正文限宽。960 时输入 620px、校样 790px，前者比后者窄四分之一，「这是我刚写的那句」在视觉上对不上；1440 展示态更糟，`.page` 放到 1120 后校样正文会拉到 900px 以上，中文一行 60 多字，读起来散。

## 5. 五个可立即落地的想法

### 想法 1 · 三处状态收成一条 44px 状态行，删掉重复的页标题（半天）

- 现状：标题块 115 + 起点 150 + 结构层声明 35 = 300px，只承载三个事实（开没开 / 源自谁 / 结构层常开）。
- 改成一行：`● 语气层 已启用 [开关] · 基于 蓝色大肥鱼 改 · 结构层常开 →`
  - 页面名交给宿主 tab，内容区不再自报家门（`tone-v3.html:265` 的 26px h1 去掉）。
  - 起点从两张 440px 卡片降级为来源标签，点「改」才展开两个选项，复用现有 `rename-pop` 的浮层样式。
  - 结构层声明并进同一行右侧。
- 用户感受：他一进来只有两个问题「开没开」「改哪句」，现在这两句答案分别在屏幕顶部和中部，中间隔着一张营销卡。
- 验收：内容区第一个可编辑控件距顶 ≤120px；全页只出现一次「语气风格」；开关与保存状态同屏。

### 想法 2 · 三句话从「表格」改成「一封短信」（1 天）

- 现在：`tone-v3.html:412` 的 `172px + 1fr` 网格，标签栏里角色徽 / 名称 / 键名 / 提示 / 看校样，四种字号；输入 620px、校样 790px。
- 改成：整块放 720px 居中列，字段名 11px 放在输入框上方一行，删掉键名、角色徽、看校样。正文口吻保留现在的 2px 锈色左边和 paper-2 底（这个已经对了），字号提到 16px / 1.72，与校样正文同级；开场和落款用 16px 单行，保留底边细线。
- 关键收益：输入与校样同宽同字号，「我写的这句就是它说的那句」成立，想法 3 才有可能收掉「看校样」。
- 顺带把整页字号从 20 档压到 5 档：22 衬线（页内唯一大标题，若保留）/ 16 衬线（语气正文与校样正文）/ 13 无衬线（标签、按钮）/ 11.5 无衬线（说明、提示）/ 10 等宽（键名、计数、图例）。
- 验收：删掉 3 个「看校样」后，用户仍能说出自己改的是哪一句；输入与校样正文字号差 ≤1px；页内字号种类 ≤5。

### 想法 3 · 校样去掉 44px 标注栏，把它推进首屏（半天）

- `tone-v3.html:634` 的 44px 栏把消息读成了 diff。层信息不丢，改挂到边上：语气行左侧 2px 锈色竖线，tab 下面一句图例「锈色是语气层，灰是结构层」。
- 删掉 `proof-caption` 那行（「普通：前缀 + 口吻 + 落款全部显示」），它与 tab 名重复。
- 表格 / 代码的 ghost 行保留，那是唯一说明「会被隐藏」的东西。
- 叠加想法 1（省 256）和想法 2（省 60）后，校样正文起点从 y≈950 前移到 y≈630，960×1000 首屏能看到结论卡、语气正文、落款三段。
- 用户感受：他不用再为先看结果付一次滚动，也就没有「差点走」的第三个触发点。
- 验收：960×1000 首屏可见结论卡 + 至少一句语气正文；无 44px 标注列；三个 tab 在首屏内。

### 想法 4 · 状态只住一个地方，保存条只剩三件事（2 小时）

- 删掉 `[Ctrl][S]`（`tone-v3.html:702`）：不是控件却长得像控件，还是全页唯一提示快捷键的地方，等于在最次要的位置暗示一个不存在的功能。
- 干净状态下主按钮不要显示「已保存」：它与左边状态行说的是同一句话。dirty 时才出现「保存」，干净时只留状态文字。
- 状态文案两行（10.5 + 8.5 等宽）压成一行 11.5：「已保存 · 新消息生效」；「历史回复不回溯」挪到开关旁的一次性说明，因为它回答的是「开了之后会怎样」，属于开关不在保存条。
- 两个实现细节：保存条 sticky 在容器末尾会脱离视口底边（校样截图里它停在 y≈915，下面空 10px 再往下就是页面尽头），给 toneShell 补一段等于保存条高度的下内距；toast 现在 `right:18 / bottom:18`，会压在保存条右侧按钮上，挪到保存条正上方或左侧。
- 验收：干净状态保存条内只有状态 + 恢复默认；点保存后状态行在一帧内变化；toast 不遮任何按钮；页尾保存条贴住视口底边。

### 想法 5 · 一键覆盖类的动作必须能撤回（2 至 4 小时）

- 这页有四个「点一下就换掉你写的东西」的动作：三个骰子（`tone-v3.html:1829` 的 `roll` 直接覆盖字段、立即标 dirty）、恢复默认（`tone-v3.html:1720`，干净状态下甚至不弹确认就覆盖）。
- 对一个「随手改两下看看效果」的场景，这是这页最主要的焦虑源，也是全页唯一没人管的 LIFT 因素：Anxiety。
- 改法都很小：骰子第一次点覆盖，再点一次撤回上一次（记一个 lastValue 即可）；恢复默认无论 dirty 与否都确认，并在保存条给一次「撤销」。
- 另外两处确认框要修：切换 tab 时弹「有未保存草稿，切换会保留草稿。继续？」（`tone-v3.html:1692`），这句在描述一个不存在的风险，确认框却在让你确认；模板切换的确认文案没说你将从谁切到谁。
- 验收：任何覆盖动作之后，一步能回到覆盖前；没有描述不存在风险的确认框。

## 7. 与 zcode 的差距：学什么，不学什么

### 该学的两件

1. **一行元信息**。A 和 B 都把「模板 / 模式 / 状态」压在一行里，40px 讲完 v3 用 300px 讲的三件事。这是单列最值钱的手艺，也正是想法 1。
2. **校样不带标注栏**。A 的右栏就是一条消息，看上去像产品；v3 的校样像调试面板。三态校样是 v3 的长处，但标注方式要换。

### 不该学的两件

1. **两栏**。A 版的两栏在 1440 下是 590 + 490，成立；压到 960，每栏只剩 430 左右，中文一行 30 字出头，正文只能回到 13px，而那正是这次要修的问题。锁定的单列不是妥协，是这套字号前提下的唯一解。
2. **B 的 card 化**。「示例」徽标、满屏胶囊、每字段独立卡片，会把一页只有三个字段的设置页做成工单系统，也和「暖纸 + 锈色 + 石墨」这套印刷气质打架。

### v3 比两个 zcode 都强的地方（别在改版里丢掉）

- 三态校样放在下方、不抢焦点，用户先配置再验证，顺序对。
- 状态矩阵更完整（未保存 / 未启用 / 无效 / 只读 / 外部变更），zcode 两版都只有「已保存」。
- 固定说明只出现一次，没有在每段重复免责。

## 8. 建议的落地顺序

1. 想法 1 + 3（半天到一天）：先让首屏出现输出。这是唯一能改变用户判断的改动，不先做它，其余优化都在给一个看不见结果的页面做美化。
2. 想法 2（一天）：输入做成结果的样子，删掉三个「看校样」。做完这一步才知道能不能连副本一起省掉。
3. 想法 4 + 5（半天）：状态收敛和可撤回。这两条直接影响「敢不敢按保存」。
4. 第 6 节的小问题随批次带走，不必单开。

三步做完再拍一次 960×1000：验收只看两条，首屏有没有一处输入加一处输出，删掉「看校样」之后有没有信息损失。

## 9. 没验证的部分

- 真实宿主内容区高度与 `CONFIG_CSS` 的实际布局能力（计划 §7 提到当前是 inline style，媒体查询写不进去）。
- 字体的实际可用性：衬线回退到 SimSun 时，16px 正文的行高观感会差一截，这一点在截图里看不出来。
- 所有「用户会怎样」的句子都是模拟，不是观察。它给出的是一组可证伪的假设，比如「删掉看校样后无信息损失」，而不是结论。
