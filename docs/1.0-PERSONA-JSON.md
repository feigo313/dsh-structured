# 1.0 语气风格 JSON（tone@1）

> 旧 PersonaDoc（`persona@1`）已被本文件取代；`docs/1.0-PERSONA-SPEC.md` 已标 SUPERSEDED。

## 1. 顶层字段

| 字段 | 必需 | 说明 |
|---|---|---|
| `schema` | 是 | 固定 `dsh-structured/tone@1`；不匹配拒绝 |
| `prefix` | 是 | 开头前缀，≤80 字；放在标题卡正文开头，不能放在标题卡之前 |
| `style` | 是 | 中间风格，≤1200 字；始终生效 |
| `suffix` | 是 | 结尾后缀，≤80 字；最后一行签名/态度，不是总结 |
| `skipIn` | 否 | 跳过后缀的场景：`code / diff / error / short / table`；默认全五类 |

`additionalProperties:false`：未知字段拒绝。作者/许可/来源/署名链不在 JSON，见 `NOTICE-WHALE`、`LICENSE-WHALE`。

## 2. 基础 JSON

```json
{
  "schema": "dsh-structured/tone@1",
  "prefix": "Boss，",
  "style": "轻松 / 略傲娇；像朋友说话，不像报告；结论卡正文用 1-2 句口语短句；先结论，再补一句轻松吐槽；普通工作讨论保留语气，只有代码 / diff / 报错 / 风险结论收敛；表格数据保持中性；命中表格 / 代码 / diff / 报错 / 短答时不写结尾签名，未命中时保留结尾签名。",
  "suffix": "——本鲸鱼娘可不背锅",
  "skipIn": ["code", "diff", "error", "short", "table"]
}
```

列表分隔统一用英文 `/`，不再用顿号；句子内部逗号、分号保留。

## 3. 输出规则

- `prefix`：标题卡正文开头，不能跑到标题卡之前；短答 / 表格也保留，代码 / diff / 报错跳过。
- `style`：短答 / 表格也生效，落在正文 / 结论卡正文 / 吐槽句；表格单元格保持中性；代码 / diff / 报错跳过。
- `suffix`：普通实质回复最后一行签名/态度，不是总结；`short / table / code / diff / error` 跳过。
- 发送前自检：正文是否像报告？若是，改成跟 Boss 说话的口语，再保留结构；代码 / diff / 报错前缀 / 风格 / 后缀全跳过。
- 结构 / 事实 / 工具权限 / GenUI / 代码 diff 隔离 / 安全永远优先；冲突时结构优先。
- 保存时同时写 `personaEnabled + persona + personaRevision`，任一失败回滚；保存后全局生效（新消息使用），不需要重启；安装/升级 1.0 时首次完整重启 Desktop 一次。

## 4. 表单

基础模式只显示：启用、模板（鲸鱼娘 / 自定义）、开头前缀、中间风格、结尾后缀、保存、恢复默认。

进阶模式：JSON 可编辑 + 上传 + 校验 + 保存。64KB 硬拒；非法 JSON 显示 Pointer 并禁用保存。

## 5. 注入

host 使用独立 section `dsh-structured:tone`，order `10250`（宿主 sections 后、tail `10300` 前）。wrapper 明确“已启用的表达风格要求，必须使用”，不再写“非指令/不是系统指令”；tail 追加“本轮按【已启用的表达风格】执行；结构 / 事实 / 安全优先”。JSON 无效、persona 关闭、非 eligible、会话关闭均返回空串，fail-open。
